# Stage 4：IP、局域网、路由与线上连接问题

## 一、阶段目标

Stage 4 解决的是一个非常实际的 UE 联机问题：

> 为什么同一局域网可以联机，换成互联网后却连接不上？

本阶段建立从“本机网卡”到“公网 Dedicated Server”的完整链路：

```text
本机配置
→ 子网判断
→ ARP 找下一跳 MAC
→ 交换机/路由器转发
→ NAT 与端口映射
→ 防火墙与端口开放
→ DNS/CDN/反向代理/负载均衡
→ Listen Server 或 Dedicated Server
```

---

## 二、IPv4、私有 IP 与公网 IP

### 2.1 IPv4 基础

IPv4 地址由 32 个二进制位组成，通常写成四段十进制数：

```text
192.168.1.20
```

每段范围是 `0～255`。更准确地说，IP 通常分配给网络接口，而不是永久绑定给整台设备。一台电脑可能同时有：

```text
有线网卡 IP
Wi-Fi IP
VPN 虚拟网卡 IP
虚拟机网卡 IP
回环地址 127.0.0.1
```

排错时不能只看“电脑的 IP”，要确认游戏实际使用哪张网卡和哪条路由。

### 2.2 私有 IPv4 地址

下面三段地址专门用于私有网络：

```text
10.0.0.0        ～ 10.255.255.255
172.16.0.0      ～ 172.31.255.255
192.168.0.0     ～ 192.168.255.255
```

不同家庭网络可以重复使用同一个私有地址，例如很多家庭都可能有 `192.168.1.20`。因为这些地址只在各自局域网内部有意义，所以不能直接作为互联网中的全局目的地址。

### 2.3 公网 IP

公网 IP 可以在互联网路由体系中被全局区分。家庭网络常见结构是：

```text
电脑：192.168.1.20
手机：192.168.1.30
主机：192.168.1.40
          ↓
家庭路由器
私网侧：192.168.1.1
公网侧：运营商提供的地址
```

家庭设备通常通过 NAT 共享路由器的公网出口。

注意：路由器管理页面显示的 WAN 地址不一定是真正可被互联网主动访问的公网地址，外层可能还有双重 NAT 或运营商级 CGNAT。

## 三、特殊地址

### 3.1 `127.0.0.1`：回环地址

`127.0.0.1` 或 `localhost` 永远表示“当前这台机器”。

```text
服务器和客户端在同一台电脑：127.0.0.1 可能有效
客户端在另一台电脑：127.0.0.1 指向客户端自己
```

如果 Dedicated Server 只监听 `127.0.0.1:7777`，本机客户端可能能连，但局域网和公网客户端通常不能连。

### 3.2 `169.254.x.x`：链路本地地址

Windows 在 DHCP 失败时可能自动配置 `169.254.x.x`。它通常说明：

```text
网卡可能已连接，但没有获得正常的 IP、默认网关和 DNS
```

优先检查网线/Wi-Fi、适配器、路由器 DHCP 和默认网关，不要先修改 UE 登录代码。

### 3.3 `0.0.0.0`

服务器监听：

```text
0.0.0.0:7777
```

通常表示在所有可用 IPv4 接口上监听 7777。它和只监听 `127.0.0.1:7777` 的可达范围不同。

路由表中的：

```text
0.0.0.0/0
```

表示默认路由，即没有更具体路由时使用的规则。

## 四、子网、子网掩码与默认网关

### 4.1 子网掩码

例如：

```text
IP：192.168.1.20
掩码：255.255.255.0
```

也可写作：

```text
192.168.1.20/24
```

`/24` 表示前 24 位是网络部分。在这个常见示例中：

```text
网络：192.168.1.0/24
常见可用主机：192.168.1.1～192.168.1.254
广播：192.168.1.255
```

`.0` 是网络地址、`.255` 是广播地址只适用于这个 `/24` 示例，不能套用到所有掩码。

### 4.2 判断是否同一子网

必须同时看 IP 和掩码。

```text
192.168.1.20/24
192.168.1.80/24
```

前 24 位相同，属于同一子网。

```text
192.168.1.20/16
192.168.2.80/16
```

前 16 位都是 `192.168`，因此也属于同一子网。不能只看第三段是否相同。

### 4.3 默认网关

本机发送数据前，会判断目标是否在本地子网：

```text
同一子网：在局域网中直接寻找目标
不同子网：先交给默认网关，再由路由器转发
```

例如：

```text
本机：192.168.5.20/24
网关：192.168.5.1
```

访问 `192.168.5.80` 时通常直接走局域网；访问 `8.8.8.8` 时先交给 `192.168.5.1`。

没有默认网关时，本机可能仍能访问同一子网的设备，但通常无法访问公网或其他子网。

## 五、MAC、ARP 与 DHCP

### 5.1 IP 和 MAC 的分工

```text
IP：跨网络定位最终目标
MAC：当前局域网这一跳定位下一张网卡
```

IP 数据包中的最终目标 IP 可以是远端服务器，但当前以太网帧的目标 MAC 可能只是默认网关的 MAC。

### 5.2 ARP

ARP 用于在局域网中查询：

```text
某个 IPv4 地址对应哪个 MAC 地址？
```

访问同一子网的服务器：

```text
判断同一子网
→ 查 ARP 缓存
→ 没有记录则广播 ARP 请求
→ 目标回复 MAC
→ 发送局域网帧
```

访问公网服务器：

```text
目标不在本地子网
→ 不查询公网服务器的 MAC
→ 查询默认网关的 MAC
→ 把帧交给路由器
```

交换机根据 MAC 转发已经封装好的帧；ARP 负责把本地 IP 找到对应 MAC，这两个职责不要混淆。

### 5.3 DHCP

DHCP 通常自动提供：

```text
本机 IP
子网掩码
默认网关
DNS 服务器
租约时间
```

常见四步可以记为：

```text
Discover → Offer → Request → ACK
```

DHCP 失败可能导致 `169.254.x.x`、默认网关为空和公网访问失败。

## 六、交换机、路由器与路由表

### 6.1 交换机

交换机主要在同一局域网内工作，根据目标 MAC 转发帧。它维护类似下面的 MAC 表：

| MAC | 端口 |
|---|---|
| MAC-A | 端口 1 |
| MAC-B | 端口 2 |

交换机会从帧的源 MAC 学习设备所在端口；如果目标 MAC 尚未学习，可能在相关端口间泛洪。

### 6.2 路由器

路由器连接不同网络，根据目标 IP 查询路由表，选择下一跳：

```text
客户端 → 家庭路由器 → 运营商路由器 → 中间网络 → 服务器网络
```

每台路由器只需要决定当前下一跳，不必掌握完整的端到端路径。

### 6.3 MAC 和 IP 在途中如何变化

链路层 MAC 通常每经过一跳就重新封装，因此会变化。网络层目标 IP 通常继续指向最终服务器；但 NAT 可能修改源 IP 和源端口。

公网 Dedicated Server 通常看不到玩家家庭网卡的原始 MAC，不能把 MAC 当作公网身份标识。

### 6.4 路由表和最长前缀匹配

简化路由表：

| 目标网络 | 下一跳/接口 |
|---|---|
| `192.168.1.0/24` | 本地网卡 |
| `10.8.0.0/16` | VPN |
| `0.0.0.0/0` | 默认网关 |

如果多条规则都匹配，通常选择前缀最长、最具体的规则。例如 `10.8.5.20` 优先匹配 `10.8.5.0/24`，而不是 `10.0.0.0/8`。

### 6.5 VPN 的影响

VPN 可能创建虚拟网卡、修改路由和 DNS、改变出口 IP，并使游戏流量进入隧道。VPN 开关前后应比较：

```text
DNS 结果
路由表
tracert 路径
实际使用的网络接口
TCP/UDP 抓包
```

## 七、NAT、端口映射与 CGNAT

### 7.1 NAT 的用途

家庭设备使用私有地址，路由器通过 NAT/NAPT 让多台设备共享公网地址：

```text
192.168.1.20:51000
→ 公网 IP:62001
```

路由器维护映射表，返回数据到达公网端口 `62001` 时，再转回原来的内网端点。

### 7.2 为什么内网能访问公网，公网不能直接访问内网

内网主动访问公网时，路由器可以根据出站连接自动创建临时映射。

公网主动访问内网时，如果没有固定映射，路由器不知道数据应该交给哪台内网设备，因此通常丢弃。

```text
能访问互联网 ≠ 公网能主动连接本机
```

### 7.3 端口映射

Listen Server 使用：

```text
192.168.1.20:7777/UDP
```

路由器可以配置：

```text
公网 UDP 7777 → 192.168.1.20 UDP 7777
```

公网端口和内网端口也可以不同：

```text
公网 UDP 30000 → 192.168.1.20 UDP 7777
```

映射必须明确：

```text
TCP 还是 UDP
公网端口
内网目标 IP
内网目标端口
```

主机私有 IP 最好通过 DHCP 保留或其他方式固定，否则地址变化后映射可能指向旧设备。

### 7.4 NAT 与防火墙不是一回事

```text
NAT：地址和端口转换、决定映射目标
防火墙：允许、拒绝或丢弃流量
```

家用路由器常同时执行 NAT 和状态防火墙，所以现象容易混在一起。映射正确不代表防火墙一定放行；防火墙放行也不代表一定有映射。

### 7.5 双重 NAT 与 CGNAT

双重 NAT：

```text
主机 → 家庭路由器 → 光猫路由器 → 互联网
```

CGNAT：

```text
主机 → 家庭 NAT → 运营商 CGNAT → 互联网
```

家庭路由器 WAN 地址如果是私有地址，或属于 `100.64.0.0/10` 共享地址范围，说明外层可能还有 NAT。仅配置家庭路由器的端口映射可能不够，因为用户通常无法配置运营商设备。

可能的解决方向：

```text
申请真正公网 IPv4
使用 IPv6 并正确配置防火墙
使用 NAT 穿透或中继服务
使用云端 Dedicated Server
```

### 7.6 NAT 回环

有些路由器支持内网设备通过自己的公网地址访问同一内网服务，称为 NAT 回环/Hairpin NAT；有些不支持。

因此：

```text
公网朋友能连接
但同一局域网使用公网 IP 不能连接
```

不一定代表端口映射失效。局域网测试优先使用私有 IP，公网入站测试使用真正外部网络。

## 八、防火墙、端口监听与公网排错

### 8.1 一个端口真正可用的条件

以 UE `UDP 7777` 为例，至少需要：

```text
UE 服务已启动
监听地址正确
协议和端口正确
Windows 防火墙允许
路由器端口映射正确
路由器有可入站公网地址
云安全组/系统防火墙允许（若部署在云端）
客户端使用正确地址
游戏层握手通过
```

“端口开放”不是单个开关。

### 8.2 监听地址

```text
127.0.0.1:7777：通常只接受本机
0.0.0.0:7777：通常监听所有 IPv4 接口
192.168.1.20:7777：只监听指定局域网接口
```

监听所有接口方便开发，但可能扩大暴露范围；生产环境应按需要绑定接口并配合防火墙。

### 8.3 TCP 与 UDP 是两套入口

```text
TCP 7777
UDP 7777
```

端口号相同也不是同一服务。UE 实际使用 UDP 时，TCP 测试成功或失败都不能直接证明 UDP 正常。

TCP 有连接建立，常见反馈较明确：

```text
Connection refused：常见于目标可达但没有监听
Connection timed out：规定时间内没有得到响应，可能被丢弃或路由不可达
```

UDP 没有握手。没有响应可能是防火墙丢弃、服务没监听、服务忽略未知数据、协议格式错误，不能仅凭通用工具下结论。

### 8.4 常用本机检查

Windows PowerShell：

```powershell
Get-NetTCPConnection -LocalPort 7777
Get-NetUDPEndpoint -LocalPort 7777
netstat -ano | findstr :7777
```

重点观察监听的是 `127.0.0.1`、`0.0.0.0` 还是局域网 IP，以及是否使用了正确的 TCP/UDP。

### 8.5 公网联机排错顺序

```text
1. 服务是否启动、监听地址/协议/端口是否正确
2. 本机回环地址是否能连
3. 本机局域网 IP 是否能连
4. 局域网另一台设备是否能连
5. Windows 防火墙是否放行
6. 路由器端口映射是否正确
7. 私有 IP 是否发生变化
8. 是否存在双重 NAT、CGNAT 或 VPN
9. 从真正外部网络测试
10. 服务器侧抓包：外部 UDP 是否到达
11. 包已到达但无法进入：检查游戏握手、版本、Token 和房间状态
```

不要只在同一家庭局域网里用公网 IP 测试，因为可能受到 NAT 回环影响。

### 8.6 现象和优先方向

| 现象 | 优先检查 |
|---|---|
| 本机回环也不能连 | 服务启动、端口、协议 |
| 本机能连，局域网不能连 | 监听地址、系统防火墙 |
| 局域网能连，公网超时 | NAT、端口映射、CGNAT、路由器防火墙 |
| 服务器完全没收到外部包 | 公网入口、NAT、映射、防火墙、运营商 |
| 服务器收到包但拒绝玩家 | 游戏版本、Token、协议和房间逻辑 |
| 登录正常但进不了对局 | HTTPS 链路正常，UDP 对局链路需单独排查 |

## 九、DNS、CDN、反向代理与负载均衡

### 9.1 DNS

DNS 负责：

```text
域名 → IP
```

它不负责证明服务器在线、端口开放、HTTP 正常或玩家鉴权通过。

一个域名可以有多个 IP，原因可能是高可用、DNS 轮询、地域解析、CDN、IPv4/IPv6 双栈或灾备。

常见记录：

```text
A：域名 → IPv4
AAAA：域名 → IPv6
CNAME：域名别名 → 另一个域名
```

DNS 结果会因 TTL 被缓存，因此修改记录后不同玩家可能暂时访问不同 IP。

### 9.2 CDN

CDN 在多个地区部署缓存节点，适合：

```text
补丁、启动器资源、图片、公告、配置、视频
```

不适合直接承载：

```text
实时 HP、背包、购买结果、匹配状态、对局位置
```

CDN 缓存命中时直接返回；未命中时向源站回源。常见缓存更新方式包括版本化 URL、内容哈希、`Cache-Control` 和主动刷新。

### 9.3 反向代理

反向代理位于公网入口与后端服务之间：

```text
客户端 → 反向代理 → 后端服务
```

常见职责：

```text
接收公网请求
TLS 终止
HTTP 转发
WebSocket Upgrade 转发
限速和基础过滤
访问日志
隐藏内部地址
```

客户端证书验证成功，只能说明客户端到反向代理的 TLS 正常，不代表后端业务成功。

### 9.4 负载均衡

负载均衡把请求分给多台后端，可以按轮询、最少连接、权重、来源、会话或健康状态选择。

健康检查正常只代表检查接口正常，不代表所有业务都正常。

如果 Session 保存在单台后端内存中，需要会话粘性、共享 Session 存储或无状态 Token，否则同一玩家请求被分到另一台后端时可能被当作未登录。

### 9.5 普通后端负载均衡不等于实时房间调度

HTTP 登录、公告、背包和匹配请求可以由负载均衡分配；实时对局通常要绑定到特定 Dedicated Server：

```text
请求匹配
→ 匹配服务分配房间
→ 返回具体 Dedicated Server 地址和端口
→ 客户端连接该对局服务器
```

不能把同一玩家的连续 UDP 包随机分给不同对局服务器。

## 十、Listen Server 与 Dedicated Server

### 10.1 Listen Server

玩家客户端同时承担客户端和服务器：

```text
玩家客户端 + 游戏服务器
```

优点：部署简单、朋友联机方便、开发测试成本低。

缺点：主机退出可能结束房间；主机网络和性能影响所有玩家；可能需要 NAT 穿透或端口映射；主机玩家可能有网络优势。

### 10.2 Dedicated Server

Dedicated Server 只运行服务器逻辑，不渲染玩家画面：

```text
多个客户端 → Dedicated Server
```

优点：持续运行、服务器权威清晰、日志集中、适合正式竞技和统一运维。

缺点：需要部署、监控、云安全组、系统防火墙和服务器成本。

登录接口和实时对局经常不是同一条链路：

```text
登录：HTTPS/TCP 443
对局：UDP 7777
```

登录成功不代表 UDP 对局端口已经可用。

## 十一、Stage 4 综合故障定位模板

遇到“局域网可连，公网不可连”时：

```text
已确认：局域网服务、部分监听和 Gameplay 逻辑可能正常
尚未确认：公网入口、NAT、端口映射、防火墙、CGNAT
验证：从真实外部网络测试，服务器侧抓包
```

遇到“登录成功但进入对局失败”时：

```text
已确认：DNS、HTTPS、登录接口和鉴权链路至少部分正常
尚未确认：匹配返回地址、UDP 端口、云安全组、游戏握手
验证：检查匹配响应、Dedicated Server 日志和 UDP 抓包
```

遇到“服务器完全收不到外部包”时：

```text
优先检查：公网 IP、路由、端口映射、CGNAT、云/系统/路由器防火墙
不要先修改：伤害、Replication 或其他 Gameplay 代码
```

故障题应按以下格式回答：

```text
已确认：
尚未确认：
候选原因：
下一步验证：
可能修复：
```
