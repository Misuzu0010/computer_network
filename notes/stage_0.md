# 阶段 0：建立网络全局视角

## 学习目标

网络通信的真正对象是“一个程序与另一个程序”。网络需要解决两个定位问题：

```text
目标是哪台设备？          -> IP 地址
目标设备上的哪个服务？      -> 端口
```

## 核心概念

### 客户端与服务器

客户端通常主动发起连接或请求；服务器通常监听端口、等待并处理请求。两者是通信角色，不是程序永久身份；一个程序可以同时承担两种角色。

### IP 地址

IP 用于在网络层定位设备或网络接口。一台设备可能有多个网络接口和多个 IP。`10.x.x.x`、`172.16.x.x` 到 `172.31.x.x`、`192.168.x.x` 是常见私网地址；`127.0.0.1` 是访问本机的回环地址。

### 端口

端口是操作系统为网络通信服务划分的编号，范围为 `0` 到 `65535`。IP 将数据送到正确设备，端口让操作系统将数据交给正确服务。

端口不等于进程：进程可以监听端口，一个进程也可以监听多个端口；TCP 和 UDP 可以分别使用同一个端口号。

客户端也有临时端口。一个 TCP 连接通常由四元组区分：

```text
源 IP + 源端口 + 目标 IP + 目标端口
```

### Socket

Socket 是程序进行网络通信的接口或通信端点。基础流程为：

```text
服务端：创建 -> 绑定端口 -> 监听 -> 接收连接 -> 收发数据
客户端：创建 -> 连接服务器 -> 收发数据 -> 关闭
```

### 协议

协议规定数据格式、字段含义、交互顺序、异常处理、确认重传和加密方式。网络可达不代表应用层协议和业务一定正确。

## 网络分层

```text
应用层：业务数据如何表达       HTTP、DNS、WebSocket
传输层：程序之间如何传输       TCP、UDP、端口
网络层：目标设备如何定位       IP、路由
链路层：当前链路如何传输       MAC、Wi-Fi、以太网
```

发送时数据逐层封装，接收时逐层解封装：

```text
[链路层头部 [IP 头部 [TCP/UDP 头部 [应用数据]]]]
```

## IP、MAC、网关与路由

- IP 更像跨网络的目的地址。
- MAC 用于当前局域网中定位下一跳网卡。
- 目标不在本地子网时，电脑通常先将数据交给默认网关（路由器）。
- 路由器根据目标 IP 决定下一跳，数据经过多个网络节点到达远端。

## 网络质量指标

- 延迟：数据传输所需时间；`ping` 常显示往返时间 RTT。
- 带宽：理论上的最大传输能力。
- 吞吐量：实际有效传输速率。
- 抖动：延迟是否稳定。
- 丢包：数据包未到达接收端。

高带宽不一定低延迟；实时应用还会受抖动、丢包和服务器性能影响。

## 访问网站的整体过程

```text
浏览器
-> DNS：域名转 IP
-> TCP：连接目标 IP:443
-> HTTPS：加密 HTTP 请求
-> 服务端处理并返回数据
-> 浏览器显示结果
```

## 常见误区

1. IP 是设备永久不变的身份证：不准确，IP 可能动态变化且设备可有多个接口。
2. 端口就是进程：不准确，端口是编号，进程可以监听端口。
3. Ping 不通就一定无法访问：不对，服务器可能屏蔽 ICMP。
4. 网络能连上就说明程序没问题：不对，还需检查端口、协议、权限和业务逻辑。
